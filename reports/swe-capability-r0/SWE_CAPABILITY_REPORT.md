# SWE 저장소 수리 역량 증폭 R0

결과는 `PASS_WITH_UNMEASURED_OFFICIAL_BENCHMARK`다. 공식 벤치마크 점수를 주장하지 않는다. 로컬에 Docker 호환 공식 하네스가 없어서 SWE-bench Verified와 DeepSWE 자체는 실행하지 않았으며, 공개 문제·정답 패치·숨은 테스트를 지식으로 수집하지 않았다.

활성 코어에는 저장소 이슈를 증거 기반 수리 DAG로 바꾸는 언어 중립 계층을 추가했다. Rust, Python, TypeScript, JavaScript, Go를 공통 수리 원자로 계획하고, Python/pytest, Rust/cargo, Node/npm, Go/go test의 저장소 네이티브 검증 경로를 제공한다. 이슈 문장만으로 패치를 고르는 경로는 닫혀 있으며 재현 가능한 실패, 공개 동작 계약, 소스 관찰이 모두 있어야 수리 계획이 열린다.

후속 증강에서는 영문·한글 이슈를 실제 동작, 기대 동작, 재현 단계, 조건, 호환성, 금지 변경, 검증 요구, 환경, 범위와 불확실성으로 분해하는 순수 Rust 의미 IR를 추가했다. 20개 신규 합성 이슈에서 명확한 16개는 모두 구조화됐고, 한영 등가 4/4, 부정 범위 8/8, 의도된 모호성 검출 4/4, 이슈 문장만으로 계획기가 열리지 않는 증거 쿼럼 검사 16/16을 통과했다. 원문은 수리 의미 기판에 저장하지 않고 절 해시와 제한된 심볼 힌트만 전달한다.

새 원자 지식은 재현, 계약 추출, 소유 심볼 탐색, 호출·데이터 흐름 절단, 경쟁 가설, 정보이득 실험, 타입·소유권, 의존성, 자원 수명, 동시성·활성, 프로토콜·직렬화, 결정성, API·데이터 호환성, 측정 우선 최적화, 최소 수정, 표적 검증, 전체 회귀, 반례 수정, 정확 롤백의 19종이다. 한 계획은 최대 18개 원자, 3개 경쟁 가설, 3회 반례 수정으로 제한된다.

신규 합성 계획 검사는 5개 언어 × 8개 결함군의 40개 과제를 수행했고 40/40이 준비 가능한 계획과 필수 원자를 생성했다. 태스크 ID 라우팅, 저장소 ID 라우팅, 참조 정답 유입, 외부 LLM 호출, 네트워크 읽기는 모두 0이다.

격리 재귀 실행은 3개 캠페인 중 2개를 독립 검증 후 승격해 generation 2에 도달했다. 첫 번째는 재현 실패와 공개 계약의 증거 합성을, 두 번째는 판별력·신뢰도·비용을 조합하는 정보이득 실험 효용을 배웠다. 중간에 `TYPED_MECHANISM_SYNTHESIS_EXHAUSTED` 반례가 발생했고 선행 메모리를 보존한 채 거부됐다. 이 반례로 기존 탐색 성공 경로를 건드리지 않는 후순위 3항 산술 합성기를 추가했고, 재시도에서 두 번째 세대가 승격됐다. 변화 없는 후속 스캔에서는 generation 2가 유지되어 정적 재검증을 지식 성장으로 세지 않았다.

현재 워크스페이스 회귀는 490/490, 그중 활성 `semantic-reasoning`은 379/379, 별도 historical 기능 회귀는 606/606 통과한다. 다만 이것은 SWE-bench/DeepSWE 실점수가 아니다. 이슈 이해는 제한되고 검사 가능한 결정적 컴파일러이지 범용 언어 모델이 아니다. TypeScript/JavaScript/Go는 계획과 네이티브 검증까지 활성화됐지만, 자동 소스 합성은 아직 Rust/Python보다 좁다.
